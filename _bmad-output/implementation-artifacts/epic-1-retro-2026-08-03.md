## 3. Patterns across the epic

### Pattern 1 — Self-referential tests, in all three stories

The single recurring defect class.

- **1.1**: 4 sabotages survived a green 6-test suite — hardcoded lattice RNG, inverted
  stone/soil layering, ids bypassing the allocator, spawn ignoring the RNG draw.
- **1.2**: 5 sabotages survived — `Ice`↔`Snow`, `Solid`↔`Ramp`, `panic!()` on every
  inbound line, x/y transposition. Review's own words: *"Same recurring class Story 1.1's
  review flagged."*
- **1.3**: raising `PEEK_DEPTH` 3→6 left all 13 tests green; the checked "out-of-depth
  blank" subtask covered nothing.

Root cause, one sentence: the test ran the oracle and the implementation through the
same function.

**The warning was already written down and it still recurred.** 1.2's Dev Notes:
*"Tests must be strong enough to fail under mutation."* 1.3's: *"Self-referential
assertions have slipped through twice."* Knowledge transferred; behaviour did not — until
1.3, where the dev agent self-verified and the mapping tests came through clean.

### Pattern 2 — Every I/O boundary shipped unbounded

Second recurring class, never named before this retro.

- **1.2 daemon**: `accept` hot-spun and wrote 2.3 GB of error log under `ulimit -n 128`;
  uncapped `lines()` took RSS 11 MB → 225 MB on 200 MB of input; no write timeout, so 20
  non-reading clients pinned 21 threads forever; unbounded thread-per-connection with an
  unwrapped `thread::spawn` on the main thread.
- **1.3 client**: no socket read timeout (a silent peer hung it forever); unbounded
  `read_line` drove RSS to 5.4 GB in 4 seconds; a decodable-but-short `tiles` array
  panicked with index-out-of-bounds.

Same defect, both shells, found by two independent reviews. Wolf overrode YAGNI both
times and was right to: "no speculative features" and "don't let one client OOM the
daemon" are not the same axis.

### Pattern 3 — The sandbox obscured the truth twice; honesty caught it both times

- **1.1**: the Dev Agent Record claimed a `simd` smoke *assertion*; no `crates/simd/tests/`
  existed. It was a manual `cargo run`. Review corrected the record.
- **1.3**: Codex's sandbox denied loopback; all six `serve.rs` tests failed
  environmentally. Reported, not worked around; orchestrator re-ran (33 green).
- **1.3, third instance (Sally)**: Codex's sandbox exports `NO_COLOR=1`, so *its* frame
  was colourless. Trusting the agent's output for FR23 would have signed off a monochrome
  icy-grim world.

### Pattern 4 — TDD discipline broke across a session boundary

1.2 was split across two Codex runs. The Debug Log records *"RED not observed because the
bridge implementation already existed"* for two whole tasks — the RED evidence was lost
between sessions, not skipped deliberately.

### Pattern 5 — One AC described something that cannot happen

New class, one instance. AC11 promised a 100×40 fallback when terminal size is
unavailable. On Linux crossterm shells out to `tput` before returning `Err`, so the
fallback is unreachable; a no-TTY frame renders at 80×24 (verified: 1,920 cells). The
code is correct; the *spec text* describes an unobservable outcome.

## 4. The structural finding

> We are paying ~$193 of Opus review to compensate for a ~$9 dev agent that writes tests
> which pass instead of tests which discriminate.

Codex codes well (3% of spend, zero scope creep, honest under pressure, improving) and
proves badly (every recurring defect class is a test-strength class). The evidence that
this is fixable at source is 1.3: the only story where the dev agent sabotage-verified on
its own, and the only story where the mapping tests came through clean. In 1.1 and 1.2
the mapping tests were exactly what fell over.

Moving discrimination into the dev phase costs roughly a dollar per story. Doing it in
review costs roughly sixty.

## 5. Wolf's decisions

### Decision 1 — Review cost: adopt all three levers for Epic 2

| Lever | Change | Effect |
| --- | --- | --- |
| A | **Blind Hunter and Edge Case Hunter → Sonnet. Acceptance Auditor and Feature Auditor stay on Opus**, as does triage | $193 → $77 |
| B | Scope each hunter to its own diff + the ACs it owns (not the whole story file, spine and PRD) | $77 → $39 |
| C | Batch mutations into one apply/revert script emitting a results table, instead of ~3 turns per sabotage | fewer turns, faster wall-clock |

**Which layers keep Opus, and why** — this is not a guess; it is the per-layer verdict
recorded after 1.3's review:

- **Feature Auditor (Opus)** drove the interactive client under a real pty. Nobody else
  had. That is where the black-on-black terminal and the unpipeable `--frame` became
  undeniable rather than theoretical.
- **Acceptance Auditor (Opus)** found the `PEEK_DEPTH` coverage hole by *sabotaging the
  constant* — no amount of reading would have surfaced it.
- **Blind Hunter + Edge Case Hunter (→ Sonnet)** were valuable but largely converged on
  the same last-hop cluster from different angles. Their unique contributions were the
  unbounded `read_line` OOM (5.4 GB in 4 s, empirically reproduced) and the
  invisible-panic-in-alt-screen observation.

**Control:** the post-patch mutation table. If Sonnet hunters propose weaker sabotages,
the kill-rate drops and it shows on Story 2.1 immediately. **Revert rule:** if 2.1's
kill-rate falls below 1.3's band, drop Lever A and keep B + C (~$96).

Baseline to compare 2.1 against — 1.3: 10 patches, 2 decisions, 3 deferred, 6 dismissed;
`PEEK_DEPTH` and `Ice`↔`Snow` sabotages both caught.

### Decision 2 — Codex sandbox: allow network, keep the offline build rules

Set `sandbox_workspace_write.network_access=true` in `scripts/codex-handoff.sh`.

**Why:** in Epic 1 the daemon was one story of three and the offline sandbox bit once. In
Epic 2 the daemon is the subject — 2.1 (delta per iteration to a connected client), 2.3
(two clients on one daemon) and 2.4 (load broadcasts a snapshot to every client) all need
a live socket; only 2.2's headless scenario harness does not. Without it, the orchestrator
becomes the test runner four times and Codex ships code it has never seen execute.

**Trade-off, accepted explicitly:** codex-cli 0.146.0's `network_access` is a boolean,
not a per-host allowlist — there is no loopback-only setting. So the closed-dependency-stack
guarantee downgrades from *sandbox-enforced* to *prompt-instructed*. `cargo fetch`
prewarm stays the orchestrator's job, Codex still builds `--offline`, and the
no-workarounds rule is unchanged.

### Decision 3 — Codex quality: adopt all three measures

Raised after the main discussion, in answer to "is there a way to improve Codex quality?"
The finding from §4 is that Codex codes well and *proves* badly. You do not fix that by
asking it to try harder — you fix it by making the proof mechanical and un-skippable.
All three adopted by Wolf, 2026-08-03.

**3a — frostvein gets its own `AGENTS.md`.** `codex-handoff.sh` runs with
`-C /workspace/projects/frostvein`; Codex reads `AGENTS.md` from the working root upward
and finds **only `/workspace/AGENTS.md`, which is a verbatim copy of the *forge's*
`CLAUDE.md`** — generic tool hygiene, and `rg -c -i 'frostvein|rust|cargo'` over it returns
nothing. frostvein has no `AGENTS.md` of its own. So Codex has never read the four-crate
layout, the gate, YAGNI-as-policy, `#![forbid(unsafe_code)]`, the commit author,
"determinism is load-bearing", or "clients contain zero game logic". All of it exists — in
`frostvein/CLAUDE.md`, under a filename Codex does not open.

Everything project-specific therefore reaches Codex only through the per-story handoff
prompt, so every rule must be restated every time and any omission is a silent gap.
**This explains the Pattern 4 failure directly:** story 1.2 spanned two Codex sessions and
the second logged *"RED not observed"* for two tasks. A new session re-reads `AGENTS.md`;
it does not re-read the prior run's handoff prompt. Durable rules in `AGENTS.md` survive a
session boundary for free.

**3b — `scripts/gate.sh` + a pre-commit hook.** There is no `Makefile`, no `justfile`, and
`.git/hooks/` holds only samples. The gate is three commands in a prompt and "green" is
whatever the agent reports. One script (fmt, clippy, test, the `cargo tree -p tui | rg
sim-core` probe) exiting non-zero, wired to pre-commit, turns *"the agent says it's green"*
into *"it could not have committed otherwise"* — closing the 1.1 record-accuracy class
(a claimed `simd` smoke assertion that did not exist) mechanically rather than by trust.

**3c — `codex review` as a pre-handback self-gate.** A real non-interactive subcommand
(`--base main`, `--uncommitted`, instructions via stdin) at Codex rates ($5/$30) against
Opus's ($15/$75). Point it at the two known recurring classes — self-referential tests and
unbounded I/O at the shell edges — before Codex hands back. **Acknowledged blind spot:** it
marks its own homework, so it supplements rather than replaces the Opus review. **Measure:**
does 2.1's Opus patch count drop below 1.3's ten?

**Not a lever:** model and reasoning effort are already maxed —
`/workspace/.codex/config.toml` sets `model = "gpt-5.6-sol"` and
`model_reasoning_effort = "high"`, and only `high`/`medium` appear anywhere in the session
history. The gains are in what Codex *reads* and what it is *forced to run*, not in how
hard it thinks.

## 6. Significant discovery — Epic 2 prep required before Story 2.1

Epic 2's plan is sound and its sequencing is right. Story 2.1 is carrying hidden scope its
text does not name. This needs one focused story-creation pass, not a replan.

1. **The TUI cannot receive a delta stream in its current shape.**
   `crates/tui/src/main.rs:121` blocks on `event::read()`. Story 2.1 requires the tick to
   climb live at 10/s; with a blocking event read the tick only advances when a key is
   pressed. Design decision needed in story-creation: `event::poll(timeout)` in the
   existing loop, or a reader thread feeding a channel.
2. **The daemon has no client registry to broadcast to.** `serve()` writes one snapshot
   then reads-and-drops forever. AD-8 deltas must reach every connected client each
   iteration — a shared client list, per-tick re-encode, and interaction with the existing
   `MAX_CONNECTIONS` (256) and `WRITE_TIMEOUT` (30 s) bounds. Story 2.3's two-client AC
   rides on this.
3. **The 1.2 half-close deferral is now due.** The `// NOTE:` in `crates/simd/src/main.rs`
   explicitly hands the dead-peer reclaim path to 2.1's delta writes.
4. **`tick: 0` becomes killable.** Epic 1's one irreducible surviving mutation
   (*"cannot be closed in this story"*) is closable once the tick loop lands. Make it an
   explicit 2.1 task.
5. **Story 2.4 carries two pre-flagged debts:** the single-RNG-stream coupling
   (deferred-work: *"Revisit at Story 2.4"*) and `rand_chacha`'s `serde` feature.
6. **FR23's final sign-off recurs in Epic 2 with motion** (epics.md). Wolf signed off the
   still frame; the moving world is a separate live gate.

## 10. Key takeaways

1. **Review cost is re-reading, not thinking.** 61% cache reads, 26% output, across 634
   turns at ~123k each. The levers are model tier, context scope, and turn count — not
   rigor.
2. **We pay $193 of review to compensate for a $9 dev agent that can't self-verify.**
   Moving sabotage-verification into the dev phase is the highest-leverage change
   available, and 1.3 already proved it works.
3. **A recurring defect class survives being written down.** Self-referential tests were
   warned about in two consecutive story files and recurred anyway. What changed it was
   making the dev agent *execute* the check, not read about it.
4. **Resource bounds at I/O boundaries are a YAGNI blind spot.** Two shells, two reviews,
   same class. Now a standing agreement.
5. **The live gate is irreplaceable.** FR23 was the last thing standing before the PR, and
   no agent could close it — one of them would have signed off a colourless world.
6. **Epic 1's story shape front-loaded infrastructure**, and Wolf felt it: no picture until
   the third story of three. A true vertical slice was actively harder here (the spine
   fixes 128×128×32 and `generate` does not support tiny worlds). Epic 2 does not repeat
   it — every story has something to watch.
7. **Codex was never reading the project's rules.** It resolves `AGENTS.md` from its
   working root and finds only the forge's generic copy; `frostvein/CLAUDE.md` is the right
   content under a filename Codex does not open. Every project rule was arriving via the
   per-story handoff prompt — which is precisely why the 1.2 continuation lost its TDD
   discipline. The fix is a file, not a behaviour change.
8. **You don't fix "proves badly" by asking an agent to try harder.** Three of the four
   quality measures adopted here remove trust from the loop rather than request more
   diligence: rules it must read, a gate it cannot fake, a mutation script it must run.
