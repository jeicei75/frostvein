## 3. Patterns across the epic

### Pattern 1 — The time-box built to save the review became the review's biggest coverage hole

| Story | Layers completing | Coverage holes |
|---|---|---|
| 3.1 | 1 of 4 | Blind, Edge Case, Feature — **all killed, zero findings between them** |
| 3.2 | 4 of 4 | none |
| 3.3 | 1 of 4 (round 1); 3 of 4 (round 2) | **Edge Case Hunter died silent twice — its territory is UNREVIEWED** |

At 3.1 the epic's most severe finding — a whole-world designate taking a delta from 378 bytes to
**16,761,209 bytes**, sustained at **34.7 MB/s** to every client, with the world simultaneously
unsaveable — was found by the *orchestrator inline*, after all three hunter layers had failed.

**The root cause was diagnosed at the Epic 2 retrospective and the fix was never encoded.** The rule
kills on wall-clock-since-launch; four layers each mandated to run `cargo test` starve on one
`target/` lock; a lock-blocked layer emits nothing and is indistinguishable from a hang. At 3.1 the
rule killed a layer that was literally reporting the contention: *"sequential due to target lock."*

This is the **same meta-failure Epic 2 identified**: an in-session fix that never reached a config
file, so the next epic inherited the trap unchanged. Epic 3 paid for it on two of three stories.

### Pattern 2 — Finding count and finding severity point in opposite directions

| Layer | Findings | HIGH | Completed | Killed at the box |
|---|---|---|---|---|
| **Acceptance Auditor** (Opus) | ~14 | **0** | 3 of 3 | never |
| **Feature Auditor** (Opus) | 6 (+1 noise) | **1** | 1 of 4 | 3.1, 3.3 r1 |
| **Blind Hunter** (Sonnet) | 1 | **1** | 1 of 4 | 3.1, 3.3 r1 |
| **Edge Case Hunter** (Sonnet) | 2 | 0 | 1 of 4 | 3.1, 3.3 r1, **3.3 r2** |
| **Orchestrator, inline** | 2 | **1** (the worst) | — | — |

The Acceptance Auditor produced fourteen findings and **not one HIGH**. The two layers that found
the genuinely dangerous things — the permanently stacked invisible stones, and the live recipe that
failed silently with exit 0 — produced seven findings between them and are the two that keep dying.

**Trimming layers by yield-count would have cut exactly the wrong ones.** This is why the Edge Case
Hunter survives this retro despite the worst record on the table: its record was produced by a
detector we now know misfires, and cutting on data from a broken instrument is cutting on noise.

### Pattern 3 — R1's evidence base collapsed, and the measurement Epic 2 built was destroyed by Pattern 1

Epic 2 justified the R1 territory split on **convergence** — the stale-speed trap (2.3) and duplicate
dwarf ids (2.4) each found independently by three layers — and left it `open` pending Wolf, with
Epic 3 meant to make it measurable.

Epic 3's **only clean four-layer story** (3.2) produced 8 findings with exactly **one** convergence:
AC10, found by the acceptance and feature auditors. **1-in-8, not 3-in-3.** The rest of the epic
cannot speak to convergence at all, because the layers that would have converged were dead.

### Pattern 4 — Spec-text defects: the Epic 3 baseline was zero. Not met — and the class relocated

Epic 2 set an explicit baseline of **zero** spec-text defects after four instances in seven stories.
The AC-authoring check worked *where it was aimed* — it caught seven defects across 3.1 and 3.2
before the stories were saved. But the class moved one step downstream, into **verification recipes**:

- **3.2**: the story's own documented Verification recipe designates at the opening view level, where
  the map is air, so AC2's diggability filter correctly marks nothing and the feature reads as broken.
  The Feature Auditor's first live run reproduced exactly that.
- **3.3**: the live recipe recorded in the Dev Agent Record was **not reproducible and failed
  silently**. Its leading `<` assumed a fixed opening camera z; the camera follows dwarf 0, who moves,
  so the auditor's run placed the pile into undug rock and captured **zero of every glyph with exit 0**.
- **3.2**: four ACs disagreed with the shipped code (the code was right in each case).

**The guard checks the AC. Nothing checks the recipe that proves the AC.**

### Pattern 5 — False evidence, third epic running. This is the project's deepest pattern

Epic 1 had `--frame`. Epic 2 had `stream_frames` recomputing the camera per frame and rendering
motion as stillness. Epic 3:

- **`scripts/mutate.sh` printed `All mutations killed.` and exited 0 when its mutations file defined
  nothing.** A truncated or syntactically broken file read as a clean sweep — in the one tool whose
  entire purpose is making a surviving mutation impossible to overlook. **AC18's evidence rested on
  it.** Found while patching 3.3, outside that story's diff, and fixed anyway.
- **The first version of that guard was itself broken** (`set -u` on a declared-but-unset array, and
  the script does not `set -e`, so it printed an error and still reported success). Both directions
  are now tested.
- **Two glyph-total claims in 3.3's Dev Agent Record were withdrawn** as not evidence of hauling —
  `☻` is co-location (a stockpile-free control run produced 1445 of them) and `≡` totals measure
  litter, because items render over zones. Only per-cell transitions stand.
- **3.2's `astar_stops_at_the_node_cap` was nearly weakened by a review finding.** The auditor read a
  0.35% margin as a fragile fixture; widening it made the mutation `MAX_ASTAR_NODES 50_000 → 60_000`
  **survive** — the story's first survivor. The tight margin is load-bearing. Reverted, with a
  `// NOTE:` explaining why, because two separate readers misread it as an accident.

### Pattern 6 — The untried cost lever was free, written down, and not followed

Review-cost rule (3) already says: run the patch pass in a fresh session, never inherit the review
transcript. **3.3's review ran in the same session as 3.3's dev** — same transcript, `2a9b9908`.

| | context re-read per turn |
|---|---|
| 3.2 review (own session) | 213k/turn |
| **3.3 review (inherited dev session)** | **493k/turn — 2.3×** |

Same shape as Pattern 1: a rule that exists, is correct, and was not enforced.

## 6. Wolf's decisions at this retrospective

### Decision 1 — Take A, B, C and E together

- **A — silence-based kill detector.** Kill a layer after N minutes with no new *named method step*
  and no new finding, plus a ~45-minute absolute ceiling so a chatty hang still dies. Replaces
  wall-clock-since-launch, which cannot distinguish a starved layer from a hung one.
- **B — per-layer `CARGO_TARGET_DIR`.** Each layer builds under its own `/tmp/review-<layer>/target`,
  so four concurrent layers stop starving on one cargo lock. Fixes the cause, not the symptom.
- **C — R1, disjoint hunter territories.** Blind Hunter = `sim-core`, Edge Case Hunter = the shells;
  both Opus auditors keep whole-diff scope.
- **E — fresh-context review and patch, enforced.** Review must not run in the dev session.

**On C, the objection and why it does not stand once A and B land.** The stated risk was
"do not narrow coverage that is already holed." A and B close the holes; with them in place, C
partitions *working* coverage rather than thinning broken coverage. The package is more coherent
than C alone would have been.

**Epic 2's revert rule is carried verbatim: revert C if a defect is later found whose site sat inside
a hunter's excluded territory.** Control = mutation kill-rate against 1.3's baseline.

### Decision 2 — Keep all four layers; re-measure on clean data

Despite the worst record on the table (2 findings, 0 HIGH, reported in 1 of 4 attempts, died silent
twice on one story), the **Edge Case Hunter stays**. Its record was produced by a detector we now know
misfires, and §3 Pattern 2 shows yield-count is anti-correlated with severity here. Judge it again
after A and B, on data that means something.

### Decision 3 — Take R2

One verification pass per review, after all patches land, rather than one per patch. Re-gate turns
are the highest cost-per-turn work in a review. **Accepted risk:** a later patch breaks an earlier
verified one, caught only by the final gate and the full mutation run — both of which are mandatory
and were green on all three Epic 3 stories.

### Decision 4 — Split Story 4.1 into two

- **4.1a — the renderer.** `v` toggle + hint bar, camera move/turn, DDA voxel traversal, reuse of the
  2D `id → RGB` table with no second mapping (AD-4), the shared cell framebuffer at the ~100 ms feel
  budget (NFR2).
- **4.1b — the creatures.** Sub-voxel dwarf models (~10×5×13 boxes-as-code), fine-step sampling inside
  creature-flagged tiles, distance LOD, seed-derived palette swaps. **FR23/FR24 sign-off lands here.**

Rationale: 4.1 as written is larger than 3.2, which was 17 ACs, cost $132.98 and exhausted a week of
Codex quota in ~3h10m. The seam is natural — different files, different risk, different failure modes
— not invented to hit a size target. Note this **reverses the 3.2 precedent deliberately**, on the
evidence 3.2 produced.

### Decision 5 — Fix the opening camera z before 4.1, not inside it

Open on a deterministic rule (e.g. the level with the most standable ground) and add an explicit
`--z` flag for captures. **Prerequisite to 4.1a**, not deferred work.

Rationale: 4.1 is a pure-camera story whose every AC will be proven by a scripted capture, and the
nondeterministic opening z is the known reason captures in this project lie. It already produced one
false *"the feature does not work"* verdict at 3.3's review.

### Team agreements

1. **"Encoded" is not "correct."** The time-box was encoded and still wrong, and the follow-through
   table said `done`. A rule that has misfired in production gets re-verified against the failure,
   not marked closed against its own text.
2. **An instrument that has never been sabotaged is not evidence.** Third epic running. `mutate.sh`
   reported a clean sweep on an empty file; the first fix of that guard was itself broken. Every
   tool that produces evidence gets a test that makes it *report failure*.
3. **A green exit code is not a result.** 3.3's recipe exited 0 having captured nothing. Range-check
   the output before drawing a conclusion.
4. **Silence from a review layer is a coverage hole, never a clean result** — restated, because Epic 3
   is the epic where it mattered most.

## 10. Key takeaways

1. **Milestone 1 is done.** The walking skeleton walks — headless and on screen — and Wolf has seen it.
2. **The fix to a fix is a fix, and it needs encoding too.** Epic 2 diagnosed the time-box misfire
   precisely and wrote it down nowhere. Epic 3 inherited it and lost coverage on two of three stories.
   The follow-through table said `done` the whole time.
3. **Yield-count and severity point in opposite directions.** Fourteen findings and zero HIGHs from
   one layer; two HIGHs from the two layers that kept dying. Any layer trimmed on count would have
   been trimmed on noise.
4. **The evidence keeps being the thing that is broken.** `--frame` (Epic 1), `stream_frames`
   (Epic 2), `mutate.sh` and two live recipes (Epic 3). Three epics, one pattern, and it has never
   been caught by the suite — only by someone running the thing and looking at it.
5. **Dollars measured the wrong axis for a whole epic.** The self-gate was 23% of cost and ~1/3–1/2
   of the resource that actually binds, and it exhausted that resource outright.
6. **FR23 is not signed off.** The feel floor is met and the "boring world" complaint is answered;
   the identity verdict moves to the depth view. Do not read 3.3's AC17 as more than it says.
