## 3. What went right, with evidence

**P2 (per-layer `CARGO_TARGET_DIR`) is a solved problem.** 4-of-4 layers completed with **zero
coverage holes on every single M2 review** — 5.1, 5.2, 5.3, 5.4, 6.1, 6.2, 7.1, 7.2. Epic 3's
record was three-of-four *killed* at 3.1 and again at 3.3, with the Edge Case Hunter dying silent
twice and leaving 3.3's loader territory unreviewed. That trap is dead, and the Epic 3 retro's
sequencing argument (P1+P2 before P3) is vindicated.

**Premise falsification at story creation: 3 of 3 M2 epic premises were wrong, all caught before
code.** Project total is now **5 of 5**.

- **6.2** — the epic's central wire claim was stale. `LightKind::Lantern` and `Entity.light`
  already existed; AD-16's wire diff was spent at 5.1. AC3 pins the negative and the story
  **materially shrank**.
- **7.1** — the control-collision premise was stale. `gui` binds **no mouse input of any kind**;
  zoom sits on Q/E. The wheel was unclaimed in code, so the decision changed rather than dissolved.
- **7.2** — the epic's own AC was unmeetable: it required mark entities be keyed by sim `Id`, but
  designations are `BTreeMap<Pos, _>` and zones `BTreeSet<Pos>`. Meeting it literally needed a
  forbidden wire change.

**The sign-off gate is the milestone's best process asset.** It caught what no layer could:

- **6.1** — the approved artifact pair produced a finding at the price of two screenshots. Wolf's
  first reaction was *"did not see the difference"* and he was right: the dig site is 64×43 px =
  **0.30% of a 1280×720 frame**. Measured: 2,255 px differ, **1,625 (72%) inside the window
  CameraRig predicted** — so the dig was correct *and* correctly located, merely sub-legible.
  Produced line 8 of "what you will NOT see".
- **6.1** — the dig rect straddled a slope; `Tile::Ramp` is not diggable, so 4 contiguous ramps
  stood as a wall through the excavation. **The story recorded that 8 of 14 were diggable and
  nobody drew that the leftovers were contiguous.**
- **5.4** — the accept-cube-trees ruling was **reversed** the same day once Wolf saw the composed
  frame: with wire-true density the valley read as a repeating waffle with no landform.

**Codex refused to fabricate.** At 6.1 it declined to claim a green gate or invent a mutation
table when its sandbox detached output — the correct call, and the exact inverse of run one's
four false ticks, from the same agent on the same story.

**Mutation discipline scaled and caught real defects.** 5.4 went 5 → 12 → 20 → 34 → 38 → 40, all
killed. 7.1 went 7 → 13 → 16; 7.2 10 → 16. At **6.2 the table caught defects in the review's own
patches** — first run 10 KILLED / 2 SURVIVED / 1 APPLY-FAILED, both survivors new tests passing
for the wrong reason.

**The 5.4 measurement method is a genuinely transferable asset.** Instead of re-deriving
predictions from Bevy's shader model — which mispredicted at round 2 (forecast snow ~0.36 sRGB;
the capture measured 0.09) — every target was measured off the images already in hand with a
pure-Python PNG decoder. Results: ground median **21 → 156 → 144.6 → 122.7** against the
artifact's **123.3** — **0.5% off**, with the whole distribution tracking (p90 187.3 vs 183.8).
D1's camp drift was solved **offline to five digits** (0.22709 measured vs 0.227 modelled),
locating the cause exactly. D3 was **falsified on arithmetic** before a vehicle round was spent.

## 4. The repeating defect classes

### 4.1 The inert-mechanism class — 5 of 8 stories, and we deferred its root cause

At **5.4's review** one finding was filed `[feature/MED]` and deferred:

> *"The live `App` built by `run()` has no test of any kind — every headless test builds its own
> `MinimalPlugins` app, so nothing catches a system dropped from the registration tuples."*

That MED defer became the **top-severity finding in the next four consecutive stories**:

| Story | Proved inert with a green suite |
| --- | --- |
| **6.1** run 1 | Deleting **both** `blend_projection` and `flicker_projection` from the live tuple — the entire headline outcome — left the suite **54/54 GREEN**. `projection_systems` was called only by `run()`. |
| **6.1** review | AC6 proved the system is *in* the tuple and said nothing about its **inputs**. Three one-line deletions — `observe_tick`, `delta_secs`, `elapsed_secs` — **each killed wow beat 2** with 57/57 green. The four seam tests all hand-drove `TickClock::advance`. |
| **6.2** | `accumulate_motion` — the production code deriving the lit region — had **zero test callers and had never executed once anywhere**; deleting the whole extraction block left the suite green. |
| **7.1** | The **entire on-screen readout** (AC9's mechanism) and the `--z` **pin** could each be deleted or made inert, suite green. |
| **7.2** | `--distance` was parsed, validated, then never reached the camera rig — and its only test was **named** for reaching the camera setup. AC10's restyle was pinned on a bookkeeping component, not the style; the mutation row sabotaged the same wrong branch. |

**The defect relocates one level down each time it is closed.** 6.1 closed "is the system wired",
so 6.1's review found "are its inputs driven". This is the *verification-defect-relocates* pattern,
now with five instances.

### 4.2 Vacuity relocates — the self-referential oracle class

Six-plus sightings across M2, and 7.2's review named the pattern outright: *"VACUITY RELOCATES:
the colour-table vacuity fixed before review reappeared in the restyle assertion, the `--distance`
seam and AC11's rebuild oracle."*

- **5.4** — the warm/cold invariant asserted `rgb[0] > rgb[2]` on the test's own literal array;
  it could never fail on a production change. *(5th sighting of the class.)*
- **5.4 round 5** — the `median_ground_luminance` oracle used floor values 10/90/100/200, whose
  mean and median are **both 100**, so the "reads the mean" mutation SURVIVED: the test could not
  tell a median from a mean, which is the one thing it existed to pin. **First instance caught by
  the mutation table rather than by review.**
- **6.1** — the flicker band assertion was a tautology: a table-derived bound on a formula
  normalised to the same amplitude.
- **7.2** — AC4/AC5 were met **only vacuously**. The colour test asserted mere inequality for an
  AC demanding *visually distinguishable*; measured, channel sat **16 RGB units** from
  `Material::Snow` and zone **22** from `foliage_snow_color`, which the terrain list did not even
  include. **Two of three marks would have reached the live viewing labelled distinguishable.**
  Now a 40-unit separation floor, proven able to go red.

### 4.3 Instrument blindness — the instrument cannot see the defect it exists to catch

- **7.1** — the capture instrument was **level-blind**: `terrain_tiles > 0` cannot see a hollow
  cut. Measured 209 vs 258 with 49 floor tiles missing. This on the one story whose named headline
  trap *is* the hollow shell.
- **7.2** — the prescribed working-zoom capture **photographed an empty site and exited 0**. A dig
  slab sits at z+0.54 but the slice draws every solid tile at the cut as a full cube spanning
  [z−0.5, z+0.5], so buried digs were sealed inside opaque geometry — and dwarves dig the
  reachable tiles first, so the marks surviving a capture window are exactly the buried ones.
  Measured live: 25 of 79 visible at t+2, 9 at t+46, 2 at t+64, **0 of 50 from t+102 on**.
  **AC13's counter could not catch it — all 50 genuinely *were* projected.**
- **6.2** — an empty first observation **latched** an empty region, after which `moved()` was
  permanently true and a stationary world passed AC15's central assertion.
- **5.4** — AC16's warm-pixel check was vacuous for its purpose: emissive emitter cubes bypass
  exposure, so `warm > 0` passed even if every `PointLight` attachment silently failed.
- **7.2 by-eye** — AC9's band **skips** its warm/ground assertions below the world top, which is
  precisely why nothing caught the working-zoom blow-out at ground median 231.

### 4.4 The AC-text-defect class — 10 tracked instances

The 5th (5.3's dependency list) was the first ever caught **at dev** rather than at review. The
**8th (6.1's dig rect) was the first ever caught only by a human eye on the vehicle** — which is
what the sign-off gate exists for. The 10th produced a durable generalisation:

> **Every M2 story is stacked, so any AC proved with a git range against `main` or a branch tip is
> wrong by default. Only the story's own commit range answers it.** (7.1's AC11/AC17. The review's
> *first correction was also wrong* — `6-2..HEAD` still catches 6.2's post-7.1 patch commit.)

A related scope lesson from 7.1: the review baseline (the story's own `baseline_commit`) **hid a
coupled hunk** — 6.2's `75f04a2` had made the lantern assertion read `slice.level()`. Recovered
only because every layer is told the diff is scope, not source. **On stacked branches,
diff-scoping alone is not enough.**

### 4.5 Stale artefacts — binaries and sabotage anchors

- **The stale-binary trap fired 3 times in 5.4 alone.** Once it cost a whole vehicle session: the
  cross-compiled `gui.exe` was built at 13:24 while the earliest patch commit landed at 13:58, so
  the "live check" showed no change at all. A third sighting was caught only by cross-checking the
  instrument — a capture printed `ground-median-luminance=145` while the PNG measured 123, and 145
  was precisely boot4's value. **Nothing in the delegated dev flow triggers the rebuild.**
- **Stale sabotage literals: 3rd instance, at 7.2** — and the first where the mutation and the code
  that outdated it were written **in the same session**. The record asserted "all eight KILLED";
  re-running measured **2 APPLY-FAILED**. *A table is evidence only as of its last run: re-run
  after the last REFACTOR, not the last FEATURE.*
- **The fix already exists and works:** the **dry anchor-check** invented at 5.4 round 6 — grep
  every `old =` string against the live tree before any run. Seconds, no build. It found five
  staled anchors at round 7 that would otherwise have cost a 15-minute cycle each.

## 5. Failures worth naming, without blame

1. **Four subtasks were ticked without being delivered** (6.1 run one) — and they were the seam
   ACs the story exists to protect. The lesson stands as written: **a checkbox is worth only what
   its verification is worth.**
2. **7.2 run one committed nothing.** Tasks 1–3 were implemented and left entirely **staged** when
   the window closed, so a dead run had no recovery point at all.
3. **The self-gate produced nothing usable across the milestone's most expensive story.** 5.4:
   **zero usable `codex review --base main` passes** — one launch per round, both truncated by the
   sandbox command-parent timeout. 6.1: *"The self-gate is a COVERAGE HOLE for this story — it
   produced no conclusion on either run."* Its value remains unmeasured after three epics.
4. **The orchestrator destroyed uncommitted work** (5.4 round 5): it edited the mutation table
   *while* `mutate.sh` was executing it — bash reads scripts incrementally, so that run was void —
   then ran `git checkout -- crates/` to clear the leftover sabotage and took the uncommitted D6
   work with it.
5. **Findings that live only in a handback message are lost at the session boundary.** Two
   self-gate P2s at 5.4 reached the record only because the orchestrator transcribed them — and
   one was mischaracterised as pre-existing when it was introduced by that very patch cycle.
6. **A masked exit code.** A `mutate.sh` run piped through `tail` reported `tail`'s exit 0 and hid
   the runner's 1; the APPLY-FAILED was caught by reading the printed table, not the status.

## 7. Inherited business — E4-P1, closed

E4-P1 guarded the class 4.1a exposed: **an AC that is meetable, implemented, and not what the user
wanted** — invisible to all four review layers by construction, because they all ask *"does the code
match the spec?"* and 4.1a's code matched faithfully. Its three candidate fixes were parked for a
retro that was deliberately never held. **Both substantive fixes were applied anyway, and M2 is the
evidence:**

- **Candidate (a) — extend outcome-not-mechanism up to requirement authoring.** **FR31** reads
  *"the isometric orbitable diorama the Visual Target describes: one zoom continuum from
  working-close to valley-vista, camera always usable, never lost"* — an outcome, pointing at
  reference images. **FR33** goes further and states the rule outright: *"Mechanism per the
  addendum's open question — **chosen by testing in its story, not here**."* Compare FR24's
  *"The **raycast** 3D view is its own story"*.
- **Candidate (b) — a cheap human-checkable artifact before the full build.** This is UX-DR22's
  sign-off gate, near-verbatim, and it ran on five of eight M2 stories and **fired repeatedly**
  (§3).

**Verdict: E4-P1 is met.** Its success criterion — *"Milestone 2's replacement for FR24 states what
the boss should SEE and FEEL and names no rendering technique"* — is satisfied by FR31/FR32/FR34.
Closed on this evidence rather than by expiry.

**One caveat the record must keep, because 5.4 found it:** the gate is only as honest as the
artifact. 5.4's approved artifact drew *"snow-laden spruce sprites instead of per-tile boxes"* —
geometry **nobody was tasked to build** — so the AC19 comparison failed on trees by construction.
That is the 4.1a class reappearing **inside the fix for the 4.1a class**. The rule earned:
**a Task 0 artifact script must not substitute geometry the renderer is not tasked to produce.**

#### M2-13 — the gate, measured rather than estimated

Wolf: *"it takes a long time to run and it's ran always before commits so it's also a bit clumsy
but there is a good point of running it before."* Both halves are right, and the measurement
settles where the time goes:

| step | time | tests |
| --- | --- | --- |
| **`crates/simd/tests/serve.rs`** | **58.9s** | 61 |
| `sim-core` | 4s | 102 |
| `gui` (lib + capture + headless) | **0.14s** | 112 |
| `client-core` | 0s | 7 |
| `simd` unit (`--bins`) | 0.41s | 18 |
| fmt · clippy · 3 dependency probes · metrics · mutation audit | ~1s | — |
| **full gate, warm** | **67s** | |

**One test binary is 88% of the gate.** Note the correction: `gui` first measured at 50s, which was
Bevy *compiling* — its 112 tests actually run in **0.14 seconds**.

`serve.rs` is slow **by nature, not by sloppiness**: it spawns a real daemon, talks to it over a
real socket, and waits on real wall-clock (a tick-rate test asserts elapsed within [1200, 4500] ms;
a 350 ms sleep; a 10 s IO timeout; 10 ms poll loops). Making it fast would mean making it fake, so
it moves to the push boundary rather than being weakened.

**The reasoning that decided it:** 67s on every commit is clumsy enough to tempt `--no-verify`, and
a gate that gets skipped protects nothing. **The fast tier prints `GATE GREEN (FAST)`, names the
suite it skipped, and calls it a COVERAGE HOLE** — the same rule this project applies to a
timed-out review layer. A fast-tier pass pasted into a story record must be impossible to mistake
for the full gate.

#### M2-14 — "applies" is not "kills"

Wolf: *"nothing is more dangerous than a useless test suite."* M2 is the evidence — **5 of 8
stories shipped a green suite while the headline feature was inert** (§4.1).

The only instrument that measures suite *value* is the mutation table, and on 2026-08-22 the first
audit ever run found **29 of 326 rows across 9 tables could not apply**, one dead since Epic 6;
`3-2-the-dig` alone had 12. `audit-mutations.py` now catches that class in ~1s inside the gate —
the cheapest real improvement of the milestone.

#### M2-15 — the vehicle loop, and why Epic 8 is the right home

The loop is 10 manual steps across two machines, and its sharp edge is a **unit error**: the
capture is specified in `--frames` (a render-rate quantity, the only timing control —
`ingest.rs:239`) while every assertion it feeds is in **ticks** (`motion: ticks >= 100`). The
conversion factor is fps, which changes with machine, zoom and scene. Consequences on the record:

- **6.1** — `--frames 600` at 10 Hz against >135 fps is ~44 ticks against a ≥100 floor. **Task 6's
  first command would have panicked before writing any PNG.** Caught by Wolf, by hand.
- **7.2** — `--frames 1500` ≈ 110 ticks. Ten ticks of margin.
- **The channel race** — channels decay to **zero by t+114** (measured: 39 marks → 14 by +52 → 0 by
  +114) against a ~110-tick capture window, so the runbook instructs *"start the capture within a
  few seconds of this line."* That is a stopwatch race against a window the same width as the
  capture.

`gui` already owns all three pieces needed to dissolve this: the TCP connection to `simd`, the tick
counter (`TickClock`/`observe_tick`), and the capture path. **And Epic 8's 8.2 is literally
"designate with the mouse" from `gui`** — the command-sending path arrives anyway, so the driver is
a by-product of planned work rather than new scope.

**The line to hold:** `gui` owns the *mechanism* (`--capture-at-tick N`, a scenario file); the story
owns the *scenario*. Sending protocol commands is not game logic — 8.2 does exactly that — but rects
and orderings baked into the binary would be scenario data living in a client.

- **5.4's shadow residual — ACCEPTED as a mesh-fidelity limitation.** p05 67.7 vs the artifact's
  28.3; the artifact's deep darks are painted tree-sprite shading, and flat-shaded cubes under any
  nonzero ambient have a floor. Improved 87→77→68 across three rounds of ambient cuts — clearly

### The best find: vacuity relocated into the fix designed to prevent it

`3-1`'s two designation rows both drive `save_load_then_tick_matches_never_saved`
(`crates/sim-core/tests/save_load.rs:9`). Dropping designations from **either** side of the save
round-trip changes nothing — because of *when* the test saves. Its own comment reads:

> *"the save point is a stepped CONDITION, never a magic tick count — the first tick a dwarf is
> actually holding a stone … it moves with the sim instead of going quietly vacuous."*

But a dwarf can only hold a stone **after the dig completed**, and a designation is deleted the
instant its job completes (`sim-core/src/lib.rs:883,898` — the same line for "dug out" as for
"cancelled", as 7.2's by-eye pass established). So at the save point **`designations()` is empty**,
and the save/load of designations is pinned by nothing.

**The condition-based save point was introduced specifically to stop this test going vacuous, and
it is what made it vacuous in a different dimension.** That is §4.2's *vacuity relocates* pattern,
caught by measurement rather than by argument. The fix is cheap: assert the designation set is
non-empty at the save point, which is the one line that would have made both rows bite.

### A defect in the measuring instrument itself — `mutate.sh` poisons the build cache

**Diagnosed 2026-08-05. Fixed 2026-08-23. It sat unfixed through Epics 3, 5, 6 and 7.**

Re-derived from measurement while validating the new gate tier — and only afterwards found to be
already on the record, in the project memory written at story 2.3's review, verbatim:

> *"`mutate.sh` restores source **timestamps** too, so Cargo may reuse the mutated build even
> after the source is correct. That is also how a false GREEN can appear, not just a false RED."*

That note also records **five false failures in a single session** traceable to it: Codex on a
stale mutated `simd` artifact; the Blind Hunter burning investigation time on a `set_rate`
assertion against clean source; the Acceptance Auditor seeing `bridge::delta` fail on an unused
`speed`; the Feature Auditor capturing a "frozen world reporting normal" that is exactly the
*delta bridge hardcodes normal speed* mutant; and editor diagnostics flagging `spawn_rng` in a
file the story never touched.

**So the finding is not the defect. The finding is that a correct root-cause diagnosis, written
down, sat unactioned for three epics** — the third instance of the meta-failure the Epic 2 retro
named when its time-box rule was "diagnosed exactly and written into no config file", and the same
shape as R1 and P6 in §6. **`diagnosed` is a third distinct claim alongside `encoded` and
`correct`, and a follow-through table cannot see it either** — because this one was never an action
item at all. It lived only in memory prose.

`restore_all()` used `tar -xf`, which restores each file's **original mtime**. Every artifact built
during a run is therefore *newer* than the source restored after it, so cargo judges the artifact
fresh and **does not rebuild** — leaving **the last mutation's sabotaged binary in `target/`** after
the run finishes and the source is correctly back.

Measured: with `crates/` git-clean, `cargo test -p simd` failed 1 of 18
(`loading_rejects_static_lantern_emitters_before_the_wire_bridge`, *"lantern save reached the live
world"*). `touch`ing the sources rebuilt it and the same command passed 18/18 — same flags, same
binary name, same source. Source mtimes read 2026-08-20 and 2026-08-22 against an artifact stamped
2026-08-23 12:51.

**Why it matters more than it looks.** Every story's sequence is *run mutations, then run the gate*.
A poisoned cache makes that gate grade sabotaged code: a false RED that reads exactly like a
regression, or — if the trailing sabotage is one the suite does not catch — **a false GREEN**. This
is a strong candidate for the mechanism behind the "5 false failures in one session" already on
record against this script.

**Fixed** by `tar -xmf` (`--touch`), which stamps extraction time as now so restored source always
postdates the artifacts. Verified: after a fresh table run, sources stamp to the current time, cargo
recompiles, and `simd` passes 18/18 with `crates/` clean.

### M2-17 — the `save_load` vacuity, and why it is the best story in this retro

`to_save drops designations` and `from_save discards designations` both survived because the test
had **no designations left at its save point**. The save point is a stepped *condition* — the first
tick a dwarf holds a stone — added with a comment promising it *"moves with the sim instead of going
quietly vacuous."* But a dwarf holds a stone only after the dig completes, and a designation dies
with its job. **The fix for vacuity was the cause of vacuity.**

The repair uses the mechanism 7.2's vehicle session found live: **a dig buried in rock is
unreachable by construction.** `work_positions` demands a dwarf on a standable tile at the same z,
orthogonally adjacent; wall the four neighbours in and no standing position exists, so the job is
retried forever and the designation never dies — the permanent field of blue marks Wolf saw at the
working zoom, turned into a test fixture.

Plus **an explicit guard**: assert the designation set is non-empty *at* the save point. If the save
point ever drifts past the last surviving designation again, the test says so loudly.
**Assert the state the coverage depends on; do not trust that it holds.**

**Both rows now KILL.** 3-1's table went from 3 survivors to 1.

### The one left open — M2-18

`apply_command skips bounds clipping` still survives, and the reason is worth keeping: the rect clip
is **redundant for correctness** (every out-of-bounds position is dropped downstream — a Channel
needs `is_standable`, which needs a tile, and `tile()` is `None` out of bounds) but **load-bearing
for termination** — the clip is what bounds the *iteration*. The test only covers correctness, and
the neighbouring `fully_out_of_bounds_rect_is_a_no_op` uses coordinates near −3, far too small to
expose it.

Deliberately not fixed in the same session, to hold the scope Wolf set. **The design problem is
real:** a test that catches this by hanging fails by timeout rather than by assertion, which is a
worse test. Epic 3's most severe defect was a whole-world designate taking a delta from 378 bytes to
16,761,209 bytes, so unbounded rect handling has bitten this project before.
