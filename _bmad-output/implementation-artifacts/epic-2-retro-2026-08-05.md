## 3. Patterns across the epic

### Pattern 1 — The instrument is the evidence, and the instrument kept being wrong

Three stories in a row shipped or inherited a defective evidence channel.

- **2.1**: the composed TUI client loop was invisible to the gate; `tui --frames N` had to
  be *invented at review* to close AC10.
- **2.2**: `--frames` recomputed the camera every frame, re-centring on entity 0, so a
  walking dwarf stayed pinned to screen centre while terrain scrolled underneath. It
  rendered **motion as stillness**, and every piece of live evidence taken through it was an
  artefact. Independently, `NO_COLOR=1` on this devpod made a colour capture containing zero
  colour information read as proof the colours worked. Both found at review, after the story
  read as done.
- **2.4**: AC11 named `--key S` *and* `--key L`; only `L` had a test. Found at review.

The rule that came out of 2.2 — an instrument carries its own test, driving the real binary,
with a mutation like any other — is now encoded in `_bmad/custom/bmad-create-story.toml` and
in `docs/technical-preferences.md`, and it visibly held for 2.3 and 2.4.

> **An untested evidence channel manufactures false evidence rather than merely missing true
> evidence — which is strictly worse than having no instrument, because it is believed.**

### Pattern 2 — Spec-text defects are now their own class

Acceptance criteria that describe something that cannot happen or contradict themselves:

- **1.3 AC11**: promised a 100×40 fallback that is unreachable on Linux.
- **2.1 AC2**: amended at review (per-drain, not per-tick).
- **2.3 AC9**: demanded a speed change appear "in the very next delta". The command crosses
  TCP and the loop drains `command_rx` at iteration top, so it lands on the *second* delta.
  Unmeetable by construction; the property FR19 actually requires (all clients flip on one
  shared tick) was met.
- **2.3 AC2**: claimed oversized lines leave the connection open while also demanding "keeps
  1.2's behaviour exactly" — 1.2 closes them. Self-contradictory.

Four instances in seven stories, all authored in create-story, all caught by review. This is
the one recurring class with no mechanical guard on it yet.

### Pattern 3 — The review layers converge, and we pay for each convergence separately

- **2.3**: the stale-speed compose trap was found independently by **three** layers.
- **2.4**: duplicate dwarf ids on load, by **three** (Edge Case Hunter live, Blind Hunter by
  inspection, and the orchestrator).
- Epic 1's retro had already recorded that the hunters "largely converged on the same
  last-hop cluster from different angles."

Four layers, each reading the same diff under the same instruction, produce roughly
one-and-a-half unique findings. The Feature Auditor is the structural exception: it asks
"is the right code present and wired?" rather than "is this code wrong?", and it has never
converged with the others.

### Pattern 4 — A review layer hung for 2.5 hours and nothing noticed

Story 2.4. A hunter layer stopped making progress and the run sat on it until Wolf returned
and spotted it — ~43% of that story's wall-clock, spent on nothing.

The compounding trap: **a growing transcript is not progress.** A hung layer keeps emitting
tokens, so file size, token count and "still running" look identical to healthy work. The
in-session fixes (port hygiene, prompt time-boxing) were applied ad hoc and — verified at
this retro — **were never written into any config file.** Epic 3 would have inherited the
same trap unchanged.

Same shape as Epic 1's central lesson, in a new place: *you do not fix this by reacting
faster.* Wolf was at karaoke, which is not a variable worth optimizing.

### Pattern 4b — The one suite with no runner was the one measuring everything

Found while applying this retro's own decisions. `_bmad/scripts/tests/test_session_tokens.py`
existed, was thorough, and **nothing ran it** — not `gate.sh`, not the pre-commit hook, nothing.
Its own docstring records the consequence: after the 2026-08-01 `PRICES` fix shipped without its
test, the suite *"went red and stayed red, unnoticed, because nothing runs it."*

Every cost conclusion in this document comes out of that script, and it is a forge-process `FILE`,
so a defect in it propagates to every sibling project. It is now the gate's fifth check
(stdlib `unittest`, no pytest, no venv, so a pre-commit hook cannot break on a missing dev
dependency), and it was **sabotage-verified before being believed**: reverting `PRICES` to the
retired rate, disabling the rollup's preservation of hand-written analysis, and billing a phase's
duration from session start instead of from its cursor each turn the gate RED.

Same shape as Pattern 1, one level up: *the instrument measuring the project had no test of its
own.*

### Pattern 5 — Every cost lever from Epic 1's retro changed where work happens, not what Claude re-reads

Epic 1's retro adopted three cost levers and predicted review would fall from $193 to $39.
Corrected against corrected: review went from **$21.44/story to $26.30/story**. It rose.

The invariant that explains it, now measurable for the first time: **96% of all tokens
processed are cache reads, in both epics.** Turns per story went 324 → 537; tokens per story
34.3M → 72.7M. The pipeline is, and has always been, dominated by re-reading context — and
none of the levers touched turn count or context size at the orchestrator, which is where
the mass is.

**What the levers *did* buy: correctness.** Patches 10 → 4, mutations 5 → 30, the
self-referential class extinct. That is a real return; it is just not the one that was
predicted.

## 4. The product finding — Epic 2 did not deliver "a world that reads as alive"

Wolf, asked whether FR23's motion sign-off closed:

> *"No. I was happy in the first stories, but eventually the world didn't change after that,
> so it was a bit boring after all."*

**This was predicted, in writing, and deferred.** 2.2's review, deferred on Wolf's call:

> *"At a default 80×24 terminal only one of the five dwarves is ever visible"* — three spawn
> on other z-levels and the fourth lands outside the viewport — *"so the headline outcome
> reads as one dwarf twitching once a second."*

Three recorded facts compound into exactly what Wolf experienced:

1. **One dwarf visible.** Live spawn positions `[99,64,20] [76,51,17] [14,94,15]
   [117,49,20] [75,33,15]`; `render` draws an entity only when `entity.pos[2] == state.z`.
2. **A blink, not a walk.** `Walk` is a one-tick pulse in eleven (`WANDER_REST_TICKS = 10`),
   so a dwarf is amber for one tick and idle for nine.
3. **Terrain never changes at all.** The dirty-tile path is inert — `set_tile` has zero
   production callers, so every delta in the whole of Epic 2 carried `tiles=[]`. The first
   real producer is Story 3.2's dig.

Epic 2's total observable motion is one dwarf, one blink per second, one tile of movement.
The epic's stated goal was *"the world reads as alive."*

**FR23's motion sign-off stays OPEN.** It is not recorded as met, and no agent may claim it.

**Wolf's decision:** do not spend a TUI story on it now — Epic 3's stories should fix it by
construction. 3.1's designation cursor puts the camera where the player is working, and
3.2's dig is the first thing that visibly changes the world. Spawn clustering is now
expensive anyway: it would move the pinned positions a third time, and 2.4's save baselines
exist as of this epic — exactly the cost 2.2 predicted for delaying.

**Alice (Product Owner):** *"We deferred the one item that turned out to be the product
outcome. That's the lesson — not the dwarf count."*

## 7. Proposal — review restructure for Epic 3

**The diagnosis, in one line:** review costs `turns × context × rate`, it is 96% re-read
context, and no lever so far has touched turns or context at the orchestrator.

**A caution this proposal has to carry:** Epic 1's retro predicted $193 → $39 and delivered
a small *increase*. So the measure below is turns and cache-read tokens — which we can now
actually read — not a dollar promise.

### R1 — Give each layer a disjoint territory instead of the whole diff

Today all four layers read the same diff under the same instruction ("find problems"), which
is why three of them found the same defect twice in two stories.

| Layer | Model | Territory |
| --- | --- | --- |
| Blind Hunter | Sonnet | `sim-core` only — sim logic, determinism, AD-7 ordering and RNG streams |
| Edge Case Hunter | Sonnet | the shells only — `simd` socket/file I/O, `tui` terminal/input (the boundary class recurring since 1.2) |
| Acceptance Auditor | Opus | the ACs, verified by execution — **whole diff, unchanged** |
| Feature Auditor | Opus | end-to-end wiring — **whole diff, unchanged** |

Each hunter's diff context roughly halves, hitting the 96% cache-read mass directly. Both
Opus layers keep whole-diff scope, so cross-crate defects stay covered.

**Risk:** a defect inside a hunter's excluded territory. Mitigated by the two full-scope
auditors, and by the revert rule below.

### R2 — One verification pass per review, not one per patch

A meaningful share of the orchestrator's 179–261 turns per review is re-running the gate and
the mutation set after each individual patch. Apply all patches, then run `gate.sh` + the
mutation set **once**; a surviving mutation costs one more cycle, not N.

### R3 — Hard per-layer time-box

Already adopted and encoded (Decision 2).

### Control and revert rule

- **Control (unchanged from Epic 1):** mutation kill-rate against 1.3's baseline. If it
  drops, the restructure is wrong.
- **New, and cheap:** record **which layer raised each finding** in the triage. Convergence
  then becomes measured rather than inferred — the thing this whole proposal rests on was
  only visible because three layers happened to be named in two story files.
- **Second measure:** turns and cache-read tokens per review, now readable straight off the
  rollup's Spend shape table.
- **Revert rule:** if a defect is later found (in 3.2 or 3.3) whose site sat inside a
  hunter's *excluded* territory, drop R1 and keep R2 + R3.

## 8. Significant discovery — Epic 3 preparation

Epic 3 is the phase-one gate (FR26, the walking skeleton). Its plan is directionally sound;
its **story sizing is not**, and two design decisions must be settled during story-creation
rather than discovered mid-implementation. This is the same shape as Epic 1's T2/T3, which
worked.

### B1 — RESOLVED: Wolf's ruling (2026-08-05) — Option C, a plain `&mut self` method

**The problem.** `simd` pauses with one branch at `crates/simd/src/main.rs:181-183`:

```rust
if speed != protocol::Speed::Paused {
    world.step();
}
```

`world.step()` runs the single schedule wired at `crates/sim-core/src/lib.rs:239`
(`(advance_tick, wander).chain()`), so pausing skips **the whole thing**. That satisfies AD-2
today only by accident — every system in that schedule happens to be world-advancing, so
"skip the world-advancing systems" and "skip everything" are currently the same action.

Story 3.1 introduces the AD-10 sim command queue (`designate`, `cancel_designation`,
`place_stockpile`), which — unlike the control commands `simd` already handles directly —
**must still apply while paused** (AD-2). Put the consumer inside the skipped branch and the
player pauses to plan, marks a rectangle, and nothing appears until they unpause.

**The three candidates considered:**

| | Approach | Why not |
| --- | --- | --- |
| A | Second always-run schedule | AD-7 says *a* single chained schedule, and 2.4 built one `assemble()` (`lib.rs:222`) precisely so a generated and a loaded world cannot diverge. Two schedules doubles what `assemble` must keep in step — the failure it exists to prevent. |
| B | One schedule + bevy run-conditions on a `Paused` resource | `sim-core` gains a pause concept. 2.3's guardrails said "no `sim-core` change of any kind"; this needs an explicit spine ruling rather than a shrug. |
| **C** | **A plain `&mut self` method on `World`, called by `simd` before the conditional step** | **CHOSEN** |

**Wolf's ruling: C.** It matches the existing precedent exactly — `World::set_tile`
(`lib.rs:375`) already mutates sim state as a plain method rather than a system. One schedule
(AD-7 intact), one `assemble` (2.4's invariant intact), pause stays entirely in `simd` (AD-2
intact), and AD-10's *"consumed at loop-iteration start"* is literally where `simd` calls it.
Least machinery, which is the YAGNI answer.

**C's cost, which 3.1 must carry as a `// NOTE:`:** command ordering is explicit by call-site
rather than by `.chain()`.

**Two things 3.1's story-creation must settle alongside it:**

1. **Where the "still applies while paused" line falls.** A designation appearing in the next
   delta while paused: yes. Does designation→job conversion run while paused? Does the
   reaction-delay counter tick? Those are world-advancing and should skip — 3.2 adds both, and
   if 3.1 does not draw the line, 3.2 draws it by accident.
2. **3.1 is a wire change, and its own text does not say so.** `designations` and `zones` are
   still `Vec<()>` at `crates/protocol/src/lib.rs:100-101` and `115-116`. Giving them real
   shapes moves `protocol`, the `simd` bridge, the pinned JSON literals and `tui` **in one
   commit or the suite is red between them** — the trap 2.2's story had to call out explicitly
   for `Entity.state`.

### B2 — BLOCKING: Story 3.2 is oversized and should be split

As written, 3.2 carries FR5 (FIFO claiming + seeded reaction delay), FR6 (dig *and* channel
execution + stone item), FR8 (unreachable retry), FR11 (A* across z-levels with ramps), FR12
(stone as a haulable item), **plus** the AD-12 job market, **plus** extending `SaveState`
(AD-11), **plus** the first-ever production `set_tile` caller, **plus** the dwarf-collision
fix deferred into it from 2.2.

Calibration: 2.4 was the largest story so far — 12 ACs, 30 mutations, $83, ~6 hours — **and
it is the one that hung.** 3.2 is materially larger than that.

**Recommended split (proposed):**
- **3.2a — the job market and the walk.** Job list + monotonic job ids (AD-12), the one
  claiming system, seeded reaction delay, A* pathfinding, dwarf walks to the site and stands
  there. `JobState::Work` becomes reachable. Observable: a dwarf you designated for
  crosses the map to the tile.
- **3.2b — the dig.** Tile mutation (the first real `set_tile` producer, so AD-8's tile half
  finally runs end to end), stone item appears, unreachable-retry, cancel-mid-dig job
  release, `SaveState` extension.

### B2 — RESOLVED: Wolf's decision (2026-08-05) — keep 3.2 as ONE story

> *"Let's keep it in one story now even though it will take time."*

The split is **not** taken. Recorded as a deliberate choice with the risk accepted, not as an
oversight. What that means in practice, since the risk does not go away by being accepted:

1. **The review half is already protected.** 2.4's actual failure was a hung review layer, and
   the time-box (Decision 2) now bounds exactly that. This is the single biggest mitigation and
   it is already in place.
2. **The dev half is the remaining exposure.** 2.4's dev ran 325 turns in one Codex session;
   3.2 will be larger and may span two. Epic 1's Pattern 4 was TDD discipline lost across a
   session boundary, and the standing runbook rule — restate RED evidence in the continuation
   handoff — **must be explicit in 3.2's handoff prompt**, not assumed.
3. **Commit boundaries are the recovery mechanism.** "One commit per green step" is already the
   rule; on a story this size it stops being style and becomes the thing that lets a failed or
   stalled run resume from the last green commit instead of restarting. Say so in the handoff.
4. **Budget the mutation-set cost explicitly.** 2.4 carried 30 mutations; 3.2 plausibly carries
   40+. `scripts/mutate.sh` is not concurrency-safe and rebuilds mutated artifacts — both 2.3
   and 2.4 hit a stale mutated binary afterwards and needed `cargo clean -p`. On a set this
   size that step is planned work, not a surprise.
5. **AC-authoring discipline matters more here, not less.** More ACs is more chances of an
   unmeetable one (P5). 2.3 shipped two on a story a third this size.

**Owner: Amelia, folded into 3.2's story-creation rather than a split.**

### B3 — Dwarf tile-collision has no acceptance criterion anywhere

Deferred to 3.2 by Wolf's call at 2.2's review, but `epics.md`'s Story 3.2 text says nothing
about occupancy or tile reservation. With A* and jobs, dwarves *converge* on dig sites, so
the failure becomes far likelier than the 2.2 repro (seed 133, ids 0 and 1 sharing a tile
for ten ticks). The symptom is a dwarf silently vanishing — the same class of
"looks-broken-to-the-player" that §4 is about. **Needs an explicit AC when 3.2 is written.**

### B4 — AD-8's tile-delta half has never run in production

Every delta in Epic 2 carried `tiles=[]`. The dirty-set mechanism is proven only by AC4's
direct `set_tile` test. Its first end-to-end exercise is the dig — a second reason not to
concentrate that in the largest story of the project.

### B5 — Three deferred items are already 3.1-owned and should be scheduled into it

Rather than re-deferred: the stale-speed compose trap (`crates/tui/src/view.rs:180-195`),
`read_inbound`'s partial-line-as-overflow misreport (`crates/simd/src/main.rs:270`), and the
missing in-UI affordance for `Command::Quit` (`crates/tui/src/view.rs:222`).

## 12. Key takeaways

1. **Review is 78% of Claude spend in both epics, and 96% of every token is a re-read.**
   That invariant survived three cost levers untouched, because none of them addressed turns
   or orchestrator context. It is now measurable for the first time, which is the
   precondition for actually testing a lever instead of predicting one.
2. **The levers bought correctness, not throughput — and that was worth having.** Patches 10
   → 4, mutations 5 → 30, the self-referential class extinct after four straight stories.
   Epic 1's prediction ($193 → $39) was simply wrong, and saying so is cheaper than
   re-deriving it next epic.
3. **What finally killed the recurring defect class was naming it in the story, by name.**
   Not "write strong tests" — 2.4's Dev Notes said "the self-referential save test is this
   story's headline trap", and Codex walked around it.
4. **Evidence channels need tests more than features do.** Three stories in a row shipped a
   broken or incomplete instrument, and a believed-but-false instrument is worse than none.
5. **We deferred the item that turned out to be the product.** 2.2's review wrote down
   "the headline outcome reads as one dwarf twitching once a second" and it was deferred;
   that sentence is Wolf's verdict on the epic, three stories later.
6. **A hung agent is a process defect, not an attention defect.** 2.5 hours were lost to a
   layer whose growing transcript looked exactly like progress. The in-session fix was never
   written down — verified at this retro — so Epic 3 would have inherited it unchanged. The
   fix is a budget the orchestrator enforces, not faster human reaction.
7. **Story size is now the leading risk indicator.** The largest story of Epic 2 was also the
   one that hung, cost the most, and carried the most mutations. Epic 3's 3.2 is larger still,
   and Wolf has chosen to keep it whole — so the mitigations move into its story-creation and
   its handoff prompt, where the size risk is actually carried.
